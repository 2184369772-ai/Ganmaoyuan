## Existing interaction audit

- The production app has three router routes but many nested work modes; treating routes alone as coverage would omit most daily workflows.
- `WorkPage` is a large stateful consumer. While a Codex run is active it polls every 2.5 seconds and replaces its local run array on every response; the polling effect also depends on that array. Unchanged responses can trigger avoidable full workbench reconciliation and timer re-registration.
- The workspace shell changes from a fixed-height app to document-flow scrolling when a top tool panel is open. This can move the conversation/composer and change scroll ownership during routine actions.
- The global stylesheet contains multiple late visual layers. The experience layer owns layout and interaction overrides; its color and font tokens mirror the existing `global.css` palette and typography rather than introducing a new brand theme.
- Inbox and other history-backed collections need bounded initial rendering while retaining explicit access to every record.
- Settings workspace configuration and scanner history load only when the project-management section is opened; leaving that section discards late responses instead of updating an inactive view.
- The workspace toolbar exposes too many peer actions, and secondary work modes were constrained to a short top panel above chat. The composer also used a separate action row and kept Stop visible while idle.

## Unified design contract

- **Character:** preserve the existing warm-neutral canvas and cinnabar accent; this milestone does not replace the app's colors or fonts.
- **Typography:** retain the existing Source Sans / Noto Sans and Source Serif token choices; use hierarchy and spacing, not a font swap, to improve scanning. Monospace remains for paths, ids, hashes, and technical evidence.
- **Surfaces:** neutral page canvas, white/dark raised work surface, subtle separators, small consistent radii, minimal shadows. Accent color means selected/current/primary only; semantic success/warning/error retain separate restrained colors.
- **Layout:** stable app shell; fixed workbench navigation and composer; one primary conversation scroll region; one independent reference sidebar scroll region; tool panels are bounded and do not resize the entire window document. Settings and home use one page scroll each.
- **Controls:** shared height, hit area, focus ring, disabled/loading behavior and button variants. Primary action per local workflow; secondary tools grouped without hiding required actions.
- **Content:** current facts and next action first; history and technical details collapsed/secondary; lists start bounded and expose explicit continuation; no business facts, statuses, or project ordering are changed by presentation work.
- **Motion/performance:** short opacity/color transitions only; no blur or large animated surfaces; reduced-motion respected; unchanged polling snapshots preserve object identity.
- **Responsive targets:** 1280x800, 1440x900, 1920x1080; no horizontal overflow or clipped action controls. Narrower supported widths collapse sidebars and keep project switching/actions reachable.

## Primary action and layout map

| Surface | Primary action and stable location | Secondary actions and layout rule |
| --- | --- | --- |
| Home / recent projects | One focus-aware primary button below the page heading; project rows open the selected project | Import is secondary; settings stays in the utility header; recent projects stay bounded to five before “view all” |
| Project conversation | Send sits at the trailing edge of the compact bottom composer; Stop appears only while a response is running | Project conversation and Codex are top-level work modes; search, context, work capture, reviews, and wrap-up are grouped under More tools |
| Codex console | The current task's state-dependent action remains on its task card | Opening Codex replaces the chat viewport with a full-height task workspace; technical evidence stays in expandable sections and history remains ordered below the current task |
| Project context / work capture / search | Each opens in the main workspace viewport, with its local copy/save/search action inside that view | Composer and unrelated chat are hidden while these modes are active; “项目对话” is the stable return action |
| Weekly review / project impact | The report's existing generate/confirm/refresh action remains in the report content | Report mode receives the main column without the unrelated composer, sidebar, or conversation history |
| Inbox / files / global results | Existing import, review, open, and file-location actions stay adjacent to their target item | Long lists keep bounded first rendering and expose explicit continuation; item detail remains on demand |
| Settings | Each section's existing save/test/restore action remains with its form or destructive operation | One section navigator, one content column, one return-to-work utility; destructive actions remain separate from routine controls |
| Shared dialogs and drawers | The dialog's confirm action stays at the end of its local action row | Details scroll inside the dialog only when necessary; close/cancel remains separate from destructive confirmation |
